# Итоговое задание «Мини-магазин школьных товаров»

Создайте одностраничный сайт на HTML, CSS и TypeScript. Посетитель должен видеть товары, находить нужные, добавлять их в корзину и оформлять учебный заказ.


**Ориентир по времени:** 4–6 часов самостоятельной работы. Если типизация DOM пока вызывает трудности, выделите дополнительное занятие.  
**Формат:** индивидуально. Дизайн можно придумать самостоятельно.

Всю логику пишите в TypeScript. Браузер должен подключать JavaScript, полученный после компиляции. Используйте обычный DOM и собственный CSS. jQuery, React, Vue и готовые UI-фреймворки в этом задании не используются. Сервер и настоящая оплата не нужны.

## 1. Какие знания понадобятся

Задание составлено по текстовому содержимому уроков 1–12 из папки [Web Programming]. 

| Материал | Что применить в проекте |
| --- | --- |
| Урок 1: HTML, изображения, ссылки, таблицы | Изображения товаров, навигация, таблица корзины |
| Урок 2: формы и семантические элементы | Структура страницы, поля заказа, select, checkbox |
| Уроки 3–4: CSS | Классы, псевдоклассы, шрифты, отступы, границы, оформление таблицы |
| Урок 5: Flexbox | Шапка сайта и панель фильтров |
| Урок 6: Grid | Сетка карточек товаров |
| Уроки 7–8: основы JS, массивы, условия и циклы | Хранение товаров, поиск, расчёты, проверки |
| Урок 9: функции | Разделение логики на небольшие функции |
| Урок 10: DOM | Создание карточек и обновление корзины |
| Урок 11: события | Обработка нажатий и отправки формы |

| TypeScript — дополнительное требование | Типы объектов и массивов, параметры и результаты функций, union-типы, проверки null/undefined |

Не нужно искусственно использовать каждую конструкцию из уроков. Например, фильтрацию разрешается написать циклом или методом `filter()`.

## 2. Структура страницы

Сделайте четыре основные части:

1. **Шапка:** название магазина, ссылки на каталог и корзину, общее количество единиц товара в корзине.
2. **Каталог:** панель поиска и фильтров, карточки товаров.
3. **Корзина:** таблица с выбранными товарами и итоговыми суммами.
4. **Оформление заказа:** форма и блок с результатом оформления.

Примените `header`, `nav`, `main`, `section` и `footer`. У страницы должен быть один основной заголовок `h1`; у разделов — свои заголовки.

Для каждого поля формы добавьте связанный с ним `label`, для изображений — осмысленный `alt`.

## 3. Исходные данные

Создайте в TypeScript массив из шести товаров:

| id | name | price, ₸ | inStock |
| --- | --- | ---: | --- |
| 1 | Тетрадь | 500 | true |
| 2 | Ручка | 200 | false |
| 3 | Рюкзак | 8000 | true |
| 4 | Карандаш | 100 | true |
| 5 | Пенал | 2500 | true |
| 6 | Альбом | 700 | true |

Добавьте каждому товару короткое описание и путь к локальному изображению. Изображения можно выбрать самостоятельно.

Начальная модель данных:

```ts
type Product = {
  id: number;
  name: string;
  price: number;
  inStock: boolean;
  image: string;
  description?: string;
};

type CartItem = {
  productId: number;
  quantity: number;
};

type Delivery = "pickup" | "courier";
```

Массив товаров должен иметь тип `Product[]`, массив корзины — `CartItem[]`. Корзина при первом открытии пустая. Цены хранятся числами, без символа валюты.

## 4. Каталог и фильтры

**Карточки формируются из массива средствами DOM.** Не копируйте шесть готовых карточек вручную в HTML.

Каждая карточка содержит изображение, название, цену, описание при его наличии и кнопку «В корзину».

Для недоступного товара покажите «Нет в наличии» и отключите кнопку. Функция добавления тоже должна проверять доступность товара.

Добавьте панель фильтров:

- текстовое поле «Поиск по названию»;
- числовое поле «Максимальная цена»;
- checkbox «Только в наличии»;
- кнопки «Применить» и «Сбросить».

Правила:

- Поиск работает по части названия без учёта регистра. Удаляйте пробелы в начале и конце запроса.
- Все включённые фильтры действуют одновременно.
- Максимальная цена включается в диапазон: при значении 500 товар за 500 подходит.
- Пустая максимальная цена означает отсутствие ограничения.
- Отрицательное или некорректное значение цены вызывает понятное сообщение. Значение 0 — допустимый фильтр, который для этих данных не найдёт товаров.
- Если совпадений нет, покажите «Товары не найдены».
- «Сбросить» очищает поля, снимает checkbox и возвращает все шесть товаров.
- Фильтрация каталога не изменяет уже добавленные позиции корзины.

Обновлять результаты достаточно по кнопке «Применить». Поиск при каждом вводе символа — по желанию.

## 5. Корзина

Показывайте корзину таблицей со столбцами: товар, цена за единицу, количество, сумма позиции, действие.

Обязательное поведение:

1. Первое добавление товара создаёт строку с количеством 1.
2. Повторное добавление того же товара увеличивает количество в существующей строке.
3. Кнопка «Удалить» удаляет всю выбранную позицию.
4. Кнопка «Очистить корзину» удаляет все позиции.
5. После каждого изменения пересчитываются таблица, сумма и счётчик в шапке.
6. Для пустой корзины отображаются сообщение «Корзина пуста», количество 0 и сумма товаров 0.

Счётчик показывает **количество единиц**, а не количество разных товаров. Две тетради и один карандаш — это 3 единицы и 2 строки.

Сумма позиции = цена × количество. Сумма товаров = сумма всех позиций. Для расчёта используйте массивы данных, а не текст, прочитанный из таблицы.

Кнопки увеличения и уменьшения количества необязательны: в основной версии количество растёт при добавлении из каталога.

## 6. Оформление заказа

Создайте форму:

| Поле | Требование |
| --- | --- |
| Имя | Обязательное, минимум 2 символа после удаления крайних пробелов |
| Email | Обязательное, поле `type="email"`; используйте проверку формы браузером |
| Способ получения | `select`: самовывоз или курьер |
| Адрес | Обязателен только для курьера; после удаления крайних пробелов не пустой |
| Комментарий | Необязательное поле `textarea` |
| Подтверждение | Обязательный checkbox «Я проверил состав заказа» |

Самовывоз стоит **0 ₸**, курьер — **1000 ₸**. По умолчанию выбран самовывоз. Показывайте отдельно сумму товаров, стоимость доставки и итог. Для пустой корзины все суммы равны 0.

При изменении способа получения пересчитывайте итог. Поле адреса при самовывозе можно скрыть или отключить; оно не должно мешать отправке формы.

При отправке формы:

1. Предотвратите перезагрузку страницы.
2. Проверьте поля и наличие товаров в корзине.
3. Если есть ошибка, покажите её и сохраните введённые данные и корзину.
4. Если всё правильно, создайте типизированный объект заказа.
5. Покажите имя покупателя, состав заказа и итоговую сумму на странице.
6. Выведите JSON-представление заказа в `pre` с помощью `JSON.stringify(order, null, 2)`.
7. Очистите корзину после успешного оформления. Созданный результат заказа должен остаться на странице.

Данные никуда не отправляются. Используйте вымышленные имя, email и адрес.

**Важно:** сохраните позиции заказа отдельным снимком данных. Последующие изменения корзины не должны менять уже показанный заказ. Пользовательский текст выводите через `textContent`.

## 7. Обязательные требования к TypeScript

- Вся написанная учеником логика находится в `.ts`.
- Включён `strict`, компиляция проходит без ошибок.
- Нет явного `any`, `@ts-ignore` или отключения строгой проверки.
- Есть типы `Product`, `CartItem`, `Delivery` и самостоятельно описанный `Order`.
- У собственных функций указаны типы параметров и возвращаемых значений. Параметры коротких callback-функций можно оставить с выведенным TypeScript типом.
- Учтено, что поиск элемента DOM может вернуть `null`, а поиск товара в массиве — `undefined`.
- Типы элементов формы проверяются перед чтением их свойств. Например, можно использовать `instanceof HTMLInputElement`.
- Числа из полей формы преобразуются из строк и проверяются.
- Значение способа доставки проверяется на `"pickup"` или `"courier"`.
- `as` и оператор `!` не используются для обхода отсутствующих проверок.

Тип `Order` должен включать данные покупателя, способ получения, необязательные адрес и комментарий, отдельный массив позиций с названиями, ценами и количеством, сумму товаров, доставку и итог.

TypeScript проверяет типы при разработке. Пустое имя, отрицательную цену и другие пользовательские значения всё равно нужно проверять во время работы программы.

Рекомендуемое разделение функций:

| Функция | Ответственность |
| --- | --- |
| `renderProducts` | Отобразить переданный список товаров |
| `filterProducts` | Вернуть товары, соответствующие фильтрам |
| `addToCart` | Найти доступный товар и добавить его в корзину |
| `removeFromCart` | Удалить позицию по ID товара |
| `calculateSubtotal` | Вернуть сумму товаров числом |
| `renderCart` | Обновить таблицу, счётчик и суммы |
| `validateOrder` | Проверить данные формы |
| `createOrder` | Сформировать отдельный объект заказа |

Можно выбрать другие названия и структуру, если обязанности функций остаются понятными.

## 8. Оформление и удобство

- Каталог разместите через CSS Grid.
- Шапку или панель фильтров оформите через Flexbox.
- Используйте единые отступы, шрифты и оформление кнопок.
- Добавьте видимые состояния наведения и клавиатурного фокуса.
- Недоступные кнопки должны визуально отличаться.
- Ошибки обозначайте текстом, а не только цветом.
- На ширине 1280 px карточки, форма и таблица должны быть читаемыми и не перекрывать друг друга.
- Адаптация под телефон — дополнительный уровень, если соответствующие CSS-приёмы ещё не проходили.

## 10. Проверочные сценарии

Каждую проверку выполняйте с указанным исходным состоянием.

| Проверка | Ожидаемый результат |
| --- | --- |
| Первое открытие | 6 товаров, ручку нельзя добавить, корзина пустая |
| Поиск «ТЕТ», остальные фильтры пустые | Только тетрадь |
| Максимум 500 и «Только в наличии» | Тетрадь и карандаш |
| Максимум 100 и «Только в наличии» | Только карандаш |
| Максимум 50 | Сообщение «Товары не найдены» |
| Максимум −1 | Сообщение о некорректной цене |
| Сброс фильтров | Снова 6 товаров |
| В пустую корзину добавить тетрадь дважды и карандаш один раз | 2 строки, 3 единицы, сумма товаров 1100 ₸ |
| Для этой корзины выбрать курьера | Доставка 1000 ₸, итог 2100 ₸ |
| Вернуться к самовывозу | Доставка 0 ₸, итог 1100 ₸ |
| Удалить тетрадь из этой корзины | Остаётся карандаш: 1 единица, 100 ₸ при самовывозе |
| Попытаться добавить ручку вызовом функции | Корзина не меняется |
| Передать несуществующий ID в функцию добавления | Программа не падает, корзина не меняется |
| Отправить заказ с пустой корзиной | Ошибка, заказ не создаётся |
| Имя состоит только из пробелов | Ошибка |
| Выбрать курьера и оставить адрес пустым | Ошибка |
| Не отметить подтверждение | Заказ не оформляется |
| Корректно оформить 2 тетради и 1 карандаш с курьером | Результат и JSON содержат итог 2100 ₸; корзина очищена |
| Добавить новый товар после оформления | Ранее показанный заказ не меняется |

## 12. Дополнительные задания

Выполняйте после основной части:

- Добавьте сортировку по цене.
- Добавьте кнопки «+» и «−». При уменьшении количества с 1 до 0 удаляйте позицию.
